## Native UI findings and corrections

Foundry's native DialogV2 resolves a submitted button callback's `null` or `undefined` to its action identifier. The earlier mocks returned the callback directly and missed this behavior.

- Outside-activity **Cancel** returned `cancel`, causing an unknown-activity notification. It now returns explicit `false`, preserving the panel state and submitting no request.
- Owner rider **Skip** returned `skip-rider`, which failed the allowed-choice check and left the GM broker waiting. It now sends a null decline immediately.
- The same correction covers GM follow-up/Vortex Skip, optional-resource Cancel, panel Close, unchecked area/movement verification, recovery acceptance and Heart of Stone damage pairing. In particular, an unchecked recovery box can no longer become the truthy `accept` action ID.
- The Suppressing Fire immunity probe included `concentrate`, which is valid on the action but rejected by the effect-trait schema. A shared `suppressingEffect()` retains visual/emotion/fear/mental for immunity testing; the action still has Concentrate.

The corrected native owner-choice harness selected Protect QA ally and then Skip, reporting **PASS** with `["ally0", null]` and four simulated private request/response messages. Both client models ran in one browser: this is not real multiplayer transport evidence.

The corrected detached panel used Burst Strike (one cartridge → zero, Hypervelocity available), canceled outside-activity recording without a request, recorded a regular reaction while preserving Hypervelocity, then recorded another action and cleared Continuation. No actor resources were actually spent.
